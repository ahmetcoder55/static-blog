Generic Repository Pattern

Her veri tabanı tablosu için ayrı ayrı CRUD kodu yazma zahmetine C# jenerikleri ile son verin.

Clean Code & DRY Standardı
📅 9 Temmuz 2026 | ✍️ Yazar: Ahmet | ⏱️ Okuma Süresi: 5 dk

Giriş: Neden Sürekli Aynı Kodları Yazıyoruz?

Bir veri tabanı projesinde çalışırken kaç kez Add(), Update(), Delete() veya GetById() metodlarını yazdınız? Eğer projenizde 20 tane tablo varsa ve her tablo için ayrı ayrı bu kodları elle yazıyorsanız, ciddi bir zaman kaybı ve kod kirliliği (code smell) ile karşı karşıyasınız demektir.

Generic Repository Pattern, tam olarak bu noktada imdadımıza yetişir. Veri tabanı operasyonlarını tek bir jenerik (şablon) yapı çatısı altında toplayarak, yüzlerce satırlık kod tekrarını sadece tek bir arayüze (Interface) indirger.

1. Sözleşmeyi Tasarlamak: IGenericRepository

İlk adım olarak, sistemimizdeki tüm tabloların (Entity yapılarının) ortaklaşa imzalayacağı jenerik bir interface oluşturuyoruz. Burada C# dilinin sunduğu where T : class kısıtlamasını kullanarak, bu şablonun sadece veri tabanı sınıflarında çalışmasını güven altına alıyoruz: 

public interface IGenericRepository<T> where T : class
{
    Task<T> GetByIdAsync(int id);
    Task<IEnumerable<T>> GetAllAsync();
    Task AddAsync(T entity);
    void Update(T entity);
    void Delete(T entity);
}

2. Entity Framework Core ile Somutlaştırma

Oluşturduğumuz bu sözleşmeyi (Interface), veri erişim katmanında (DAL) EF Core altyapısını kullanarak tek bir seferde dolduruyoruz. Artık projedeki tabloların hiçbiri için ayrı ayrı CRUD metodu gövdesi yazmayacağız: 

public class GenericRepository<T> : IGenericRepository<T> where T : class
{
    protected readonly DbContext _context;
    private readonly DbSet<T> _dbSet;

    public GenericRepository(DbContext context)
    {
        _context = context;
        _dbSet = _context.Set<T>();
    }

    public async Task<T> GetByIdAsync(int id) => await _dbSet.FindAsync(id);

    public async Task<IEnumerable<T>> GetAllAsync() => await _dbSet.ToListAsync();

    public async Task AddAsync(T entity) => await _dbSet.AddAsync(entity);

    public void Update(T entity) => _dbSet.Update(entity);

    public void Delete(T entity) => _dbSet.Remove(entity);
}

3. Mimari ve Siber Güvenlik Açısından Avantajları

Generic Repository sadece kod kısaltmaz, kurumsal sistemlerde çok daha derin mimari faydalar sağlar:

🛡️ Merkezi Güvenlik ve Validasyon: Veri tabanına atılan tüm sorgular tek bir merkezden geçtiği için, sql injection veya yetkisiz veri erişimi gibi güvenlik açıklarını engelleyecek küresel filtreleri (Global Query Filters) bu katmana tek seferde uygulayabilirsiniz.
🔄 Teknolojiden Bağımsızlık: Yarın bir gün Entity Framework Core yerine Dapper veya başka bir ORM kütüphanesine geçmek isterseniz, üst katmanlardaki (Business/API) hiçbir koda dokunmadan sadece bu sınıftaki kodları değiştirmeniz yeterlidir.

Sonuç

Generic Repository Pattern, özellikle Unit of Work deseniyle birleştiğinde veri tabanı işlemlerinde kusursuz bir atomik yapı (Transaction yönetimi) sunar. Projenizin büyüklüğü ne olursa olsun, bu yapıyı kurmak temiz kod (Clean Code) standartlarının en temel kuralıdır.
